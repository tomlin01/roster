本次啟用：4 個 role-agents（體驗策劃、資訊架構、選擇紀錄、風險收斂）
目前階段：初步拆解；這輪不產出正式簡報、網頁、遊戲規則或展示稿。

我會先把它拆成一個 3 分鐘體驗迴圈：

1. **理解這個地方**
   目標不是完整世界觀，而是讓使用者在 30-45 秒內知道：這座漂浮城市是什麼、夜市在哪裡、為什麼值得選一個攤位。

2. **快速比較攤位**
   第一輪不要鋪太多攤。建議先用 3-5 個攤位，每個攤位只保留一個清楚差異：味覺、風險、故事線索、獎勵、社交性或稀有性。

3. **做出第一個選擇**
   使用者需要一個簡單決策依據，例如「想安全探索」、「想吃最奇特的」、「想找線索」、「想賭高風險高回報」。

4. **留下可追蹤紀錄**
   紀錄不該只是「選了 A 攤」，而要至少保留：選擇、選擇理由、當下偏好標籤、時間點或路線狀態。這樣未來轉成簡報、互動網頁或遊戲時都能接上。

第一輪該確認的事：

- 使用者是誰：觀眾、玩家、投資/評審、展場訪客，還是課堂/研究展示對象。
- 3 分鐘後要留下什麼印象：驚奇感、地方理解、想繼續探索，還是明確選擇資料。
- 漂浮城市的調性：奇幻、賽博龐克、台灣夜市變體、觀光導覽、或遊戲世界。
- 攤位選擇的核心變數：食物、故事、任務、風險、資源、角色互動，哪一個是主軸。
- 追蹤紀錄的用途：只是展示互動結果，還是未來要分析使用者偏好與路線。
- 這輪先不決定媒介，但要決定「共用骨架」：場域介紹、攤位卡、選擇理由、紀錄格式。

最容易走偏的地方：

- 世界觀寫太滿，導致 3 分鐘內使用者還沒開始選。
- 太早決定要做成簡報、網頁或遊戲，反而讓核心體驗被媒介綁住。
- 攤位過多，每個都很有趣，但沒有決策差異。
- 只做氣氛導覽，沒有真正的「先去哪一攤」。
- 留下紀錄但沒有理由欄位，後續無法追蹤為什麼選。
- 把它做成故事閱讀，而不是短時間內可行動的導覽。
- 遊戲規則太早膨脹，讓夜市導覽變成複雜系統設計。

本次分工執行：
- 體驗策劃：把任務收斂成 3 分鐘「理解 → 比較 → 選擇 → 紀錄」迴圈。
- 資訊架構：指出第一輪需要確認的場域、攤位與選擇依據。
- 選擇紀錄：定義紀錄要保留的不只是結果，還要有理由與偏好標籤。
- 風險收斂：列出最容易讓專案走偏的方向。

最後收斂：第一輪應該先確認「3 分鐘決策迴圈」和「可追蹤選擇紀錄」，暫時不要寫正式內容或鎖定媒介。
