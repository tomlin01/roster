目前階段：初步規劃；正式 artifact 這輪先不產出。

我的初判是：問題可能不在「能不能產出簡報」，而在「資源從來源到投影片物件之間沒有穩定合約」。也就是資料、圖片、圖表、版面模板各自可用，但整合時缺少可追蹤、可重跑、可視覺驗收的流程。

**可能問題層次**

1. **來源合約不穩**
   每張投影片需要哪些資料表、圖片、圖表、文字、來源版本、授權或解析度，可能沒有 manifest 管住。結果是簡報看似完成，但難以知道哪個物件來自哪個來源。

2. **資源形態邊界混亂**
   圖片、裝飾、背景適合 raster/PNG；文字、表格、圖表通常應保持 PowerPoint 或可編輯原生物件。若流程把應可編輯的內容全部變成圖，或把生成圖片硬當成可編輯圖表，後續修正會很不穩。

3. **轉換鏈沒有明確中間產物**
   例如 `data -> chart -> image/export -> slide placement -> final deck`，每一步若沒有固定檔名、輸出目錄、重跑規則、失敗訊號，就會變成「這次有跑出來」但不可診斷。

4. **版面整合缺少視覺驗收**
   常見問題會是遮擋、比例錯、圖表字太小、圖片裁切錯、對比不足、匯出 PDF/PNG 後和 PPT 內看到的不一致。這類問題不能只看原始檔，要看 render/export 後的畫面證據。

5. **缺少 slide-level traceability**
   下一輪應能回答：「第 7 張的圖表來自哪個資料、哪個腳本、哪個輸出檔、哪個版面槽位？」如果答不出來，整合流程本身大概率有問題。

6. **品質檢查太靠最後一眼**
   若流程只在完成後人工掃一遍，而不是每一類資源都有進場檢查、轉換檢查、放版檢查、輸出檢查，就容易出現反覆修補。

**怎麼檢查是不是流程本身有問題**

先不要看整套系統，挑一份近期「看起來有產出但你覺得不穩」的簡報，做一個小型追蹤：

- 抽 3-5 張代表性投影片：一張資料型、一張圖表型、一張圖片重的、一張版面複雜的。
- 對每張列出 source inventory：資料檔、圖片檔、生成圖、圖表腳本、模板、最終投影片物件。
- 檢查是否能從最終投影片反查來源與版本。
- 重新跑一次資源產生流程，看輸出是否 deterministic：檔名、尺寸、樣式、位置是否一致。
- 匯出成 PDF 或 PNG，再檢查可讀性、遮擋、裁切、比例、缺漏。
- 比對 PPT 內視覺結果與 export 結果是否一致。

如果這幾步中出現「找不到來源」、「需要猜哪個檔案是最新」、「重跑後 layout 改變」、「PPT 看起來正常但匯出壞掉」，那問題就不是單一 artifact，而是資源整合流程。

**下一輪先看什麼證據**

優先看這五類，不需要一開始就全面 review：

1. 一份實際輸出的 `.pptx` 或匯出 PDF/PNG。
2. 該簡報用到的原始資料、圖片、圖表輸出資料夾。
3. 產生簡報的腳本、prompt、模板或操作步驟。
4. 最近一次出問題的具體例子：哪幾張、什麼不穩、最後怎麼修。
5. 是否已有任何 manifest、README、命名規則、檢查清單或輸出 log。

下一輪我建議先做「流程證據盤點」，不是正式 review：只回答三件事，來源鏈是否可追蹤、重跑是否穩定、視覺輸出是否有可驗收證據。這會比直接改簡報或重寫流程更快定位問題層級。
