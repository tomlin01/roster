目前階段：初步規劃；正式 artifact 這輪先不產出。

我會先把它拆成「3 分鐘決策導覽」，不是先拆成簡報、網頁、遊戲或原型。核心任務是：讓使用者快速知道這是什麼地方、理解少數可比較的攤位、做出第一站選擇，並留下可追蹤紀錄。

**建議拆法**

1. 體驗主線：3 分鐘內的注意力流程  
   例如：入口印象 -> 方向感 -> 3 到 5 個候選攤位 -> 選擇 -> 紀錄。

2. 場域規則：漂浮城市不只是背景  
   要先決定它如何影響夜市：移動路線、天氣/高度、交通、能源、攤位分布、風險或奇觀。

3. 攤位選擇模型：使用者憑什麼先去哪  
   不是先寫很多攤位，而是先定比較維度：口味、稀有度、排隊時間、故事線、預算、風險、獎勵。

4. 可追蹤紀錄：記錄「決策」而不是只記結果  
   最小紀錄應包含：看過哪些選項、選了哪攤、選擇理由、時間點或階段、是否可回頭比較。

5. 未來輸出分流：先保留，不提前綁死  
   簡報重敘事節奏；互動網頁重導覽與點選；遊戲規則重選擇成本；展示原型重可操作流程。這輪只要定共同骨架。

**第一輪該確認**

- 目標使用者是誰：觀光客、玩家、評審、投資人、課堂觀眾，還是內部團隊？
- 「理解這個地方」最低標準是什麼：知道世界觀、知道路線、知道攤位差異，還是知道自己為何要去？
- 3 分鐘是嚴格倒數，還是設計上的注意力上限？
- 第一輪要比較幾個攤位：我建議先限制在 3 到 5 個。
- 選擇紀錄的用途是什麼：個人回顧、後續推薦、遊戲狀態、研究紀錄，還是展示用證據？
- 這個導覽的語氣是沉浸式、實用型、遊戲化，還是展覽導覽型？

**容易走偏的地方**

- 太早世界觀膨脹：漂浮城市寫得很完整，但使用者還是不知道先去哪。
- 太早選媒介：一開始就做成簡報或網頁，結果流程被工具限制。
- 攤位太多：夜市感變強，但 3 分鐘決策會崩掉。
- 紀錄太重：做成資料系統，反而忘了使用者只是在選第一站。
- 浮空設定變裝飾：如果「漂浮」不影響路線、視野、風險或選擇，它只是美術風格。
- 遊戲化過早：積分、任務、道具太早進來，會把導覽目標蓋掉。
- 沒有驗收標準：最後看起來有趣，但無法判斷使用者是否真的理解並完成選擇。

第一輪的成功標準可以很簡單：使用者看完後能用一句話說出這個地方是什麼、能比較少數攤位、能選出第一站並說出理由，而且這個理由被留下來。下一步適合做「v0 範圍界定」，仍不寫正式內容，只鎖定受眾、3 分鐘流程、攤位比較維度與紀錄欄位。
